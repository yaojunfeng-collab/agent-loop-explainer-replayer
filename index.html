Agent Loop 核心概念

🧵

Thread（线程/会话）

用户从打开 Codex 到关闭的整段会话。一个 Thread 可以包含多个 Turn。在 Codex 里，每个 Thread 都有唯一 ID，rollout 日志按 Thread 组织存储在 ~/.codex/sessions/ 下。

ThreadId = uuid::Uuid
🔄

Turn（轮次）

用户发出一条指令，到 Agent 完成这次任务的完整处理单元。用户视角看到的"一问一答"，但内部可能包含数十个 Step。Turn 是奖励评估的自然边界。

turn_context → response_items → TurnComplete
⚡

Step（步骤）

在一个 Turn 内，模型的每次推理决策。输入是 "当前累计上下文"，输出是 "下一个动作"（工具调用 or 最终答复）。Step 是 RL 的策略优化单元。

state_t → action_t → state_{t+1}
🤖

模型输入（Responses API 视角）

每个 Step 调用模型时的完整输入，包含 4 层：system（平台规则）→ developer（应用规则）→ user（当前请求）→ 历史 tool 结果。随 Step 推进，输入以 append-only 方式增长。

{ input: [developer, user, tool_outputs...] }
🎓

RL 与 Agent Loop 的关系

Agent Loop 是 RL 的"运行时环境"：loop 收集轨迹（trajectories），RL 对轨迹打 reward，再反向优化每一个 Step 的动作概率。Step = (state→action) 决策点。

trajectory = [s0→a0, s1→a1, ..., sn→reward]
🔧

Codex 的 Append-Only 策略

稳态下，Codex 不覆盖旧消息，只追加新增量。切换 Plan/Default 模式时，先更新 session state，下一次 Turn 到来才在 history 里追加新的 developer update item。

s1 = s0 + Δ1, s2 = s1 + Δ2
